# Handover 01: scaffold + scrape

Read `AGENTS.md` first. This phase collects raw reviews. No LLM calls, no site work.

## Goal

Produce `data/raw_reviews.csv`: every Perplexity review from Google Play and the Apple App Store
dated within the last 90 days of the run date (UTC), capped at 20,000 rows, with no personal data.
Plus a volume report so Claude can see what we actually got.

  "Perplexity - Ask Anything".
- App Store id: `1668000334`, bundle `ai.perplexity.app`, "Perplexity - AI Search & Chat".

## Build

```
requirements.txt  .env.example  .gitignore  README.md
pipeline/config.py            app ids, country list, window days, cap, seed
pipeline/scrape_play.py       -> data/interim/play.jsonl
pipeline/scrape_appstore.py   -> data/interim/appstore.jsonl
pipeline/merge.py             -> data/raw_reviews.csv + data/volume_report.md
tests/                        fixtures + pytest
```

### Google Play (`scrape_play.py`)

- Use the `google-play-scraper` Python package, sorted newest first, paginating with its
  continuation token. Stop a stream once a full page is older than the window.
- Play reviews are served per language/country pair. Loop over the pairs in `config.py`, starting
  with: en-US, en-IN, en-GB, hi-IN, es-MX, es-ES, pt-BR, de-DE, fr-FR, ja-JP, ko-KR, id-ID, ar-AE,
  tr-TR, it-IT, ru-RU, vi-VN, th-TH. Dedupe on the review id. Report rows per pair so we can see
  which ones add anything.
- Be polite: small delay between pages, retry with backoff, exit non-zero on a block.

### App Store (`scrape_appstore.py`)

- Use the RSS JSON feed above with `requests`. No scraping library needed.
- Storefronts: us, gb, in, ca, au, de, fr, es, br, mx, jp, kr, id, sg, ae. Page until an empty page,
  an error, or the window edge.
- The first page sometimes includes an entry that is the app itself, not a review (no `im:rating`).
  Skip those.

### Merge (`merge.py`)

Output columns, in this order:

| Column | Notes |
|---|---|
| `review_id` | `play_<id>` or `ios_<id>`. Stable across reruns. |
| `platform` | `android` or `ios` |
| `country` | two-letter storefront; for Play, the country of the pair that first returned it |
| `timestamp` | ISO 8601, UTC |
| `date_utc` | `YYYY-MM-DD` |
| `rating` | integer 1-5 |
| `title` | iOS only, else empty |
| `review_text` | body as written. Don't clean, translate, or truncate. |
| `app_version` | may be empty |
| `thumbs_up` | Play `thumbsUpCount` or iOS `im:voteSum` |
| `has_dev_reply` | TRUE/FALSE. Play only, else FALSE. Don't store the reply text. |

- Drop rows with empty `review_text`. Dedupe on `review_id`.
- Window: `timestamp >= run_time_utc - 90 days`. Record the run time in the report.
- Cap: if rows exceed 20,000, downsample uniformly within each (platform, date_utc) group with the
  fixed seed in `config.py` so each platform-day keeps the same share. Write the pre-cap counts per
  platform-day to `data/daily_true_counts.csv` either way. The volume chart needs true counts.
- Reviewer name, avatar, and profile URL must not appear in any output, interim file, or fixture.
  Strip them at parse time.

### Volume report (`data/volume_report.md`)

Generated by `merge.py`, not written by hand: run time, total rows before and after cap, rows by
platform, by country, by week, by star rating per platform, median and p90 review length in
characters, share of reviews under 4 words, share with non-ASCII text, earliest and latest date per
platform, App Store pages served per storefront.

### Tests

- Parser tests for both sources against small saved fixtures (scrub names before saving).
- Dedupe, window edge (a review exactly 90 days old), cap sampling (deterministic, per-group share
  preserved within rounding), and a test asserting no output column or fixture key matches
  `author|userName|userImage|name|uri`.
- `pytest` passes with the network off.
